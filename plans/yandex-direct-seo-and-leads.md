# SEO, Яндекс Директ и измерение лидов

## Результат

Обновить главную под одну бесплатную карту без регистрации, сохранить существующие SEO-страницы и подтверждение Яндекс Вебмастера. Подключить Метрику по реальному ID счётчика и разрешению на аналитику. Основной лид — успешное подтверждение email, остальные этапы воронки учитываются отдельно. Дать пошаговую инструкцию настройки Директа и оценки цены лида.

По прямому указанию пользователя убрать сообщение о подготовке документов и искусственный запрет регистрации/оплаты. Сохранить одну галочку регистрации, реальные версии опубликованных текстов, проверку email, настройку платёжного провайдера, проверку webhook и принадлежности оплаты.

## Реализация

1. Проверить прошлые сессии. Повторно использовать существующее подтверждение Вебмастера, уже настроенную ЮKassa и исправленную отправку почты через HTTPS REG.RU из main. Не переписывать секреты и не перезапускать настройку с нуля.
2. Согласовать статические SEO-тексты, canonical и JSON-LD главной с гостевым сценарием. Личные страницы остаются noindex, UTM/yclid не создают новые canonical.
3. Убрать frontend legalPublication gate; предоставить frontend и backend общий действующий каталог опубликованных документов с настоящими хешами. Не выдумывать реквизиты владельца и договоров.
4. Загрузить Метрику только после согласия. События: guest_reading_started, guest_preview_viewed, registration_started, registration_submitted, email_verified, guest_reading_unlocked, payment_started, payment_completed. Передавать только фиксированные имена целей и безопасные URL/технические UTM; не передавать email, ID пользователя, вопрос, текст расклада, токены или свободный поисковый текст.
5. Отмечать успешную покупку только по подтверждённому сервером заказу текущего пользователя. Проверять реальную готовность провайдера; пользователь с ранее действовавшей подпиской не создаёт ложную конверсию.
6. Подключить build env и точные CSP origins. Подготовить руководство для реального ID, целей Метрики, Директа, UTM, проверки конверсий, CPL и Вебмастера.

## QA / verification

- Frontend: npm run type-check, npm test, npm run build.
- Backend: dotnet test backend/FutureViewer.slnx с PostgreSQL/Testcontainers.
- Автоматизированная браузерная проверка гостевой воронки и регистрационной формы на desktop/mobile; проверить события со stub-счётчиком без реальных запросов в Метрику.
- Rendered browser QA через Browser Use/in-app browser: главная и регистрация, отсутствие заглушки, одна галочка, читаемость на мобильном экране.
- Проверить каталоги/версии документов без env approvals, отказ от cookies, удаление аналитического состояния при отзыве, отсутствие токенов/личных URL в событиях и дедупликацию подтверждения email/покупки.
- Проверить доступ к статусу только своего заказа; подтверждение покупки требует статуса Paid после проверенного webhook.

## Публикация

В текущем запросе изменения production не поручены. Готовим и проверяем код локально; реальный счётчик активируется после указания его ID и пересборки. Рекламную кампанию и расходы пользователь настраивает по инструкции. Никаких новых оплат или рассылок для QA.
