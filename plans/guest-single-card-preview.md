# Быстрый гостевой расклад

## Реализация
- Главная для гостя: одна карта, необязательный вопрос с безопасной формулировкой по умолчанию, прямой запуск анимации без входа.
- Отдельный публичный API создаёт только одну карту и возвращает примерно половину толкования. Полный результат защищён сервером; действует 24 часа и раскрывается только после входа/подтверждения почты.
- Сохранять только зашифрованный билет продолжения в браузере. После регистрации открывать тот же расклад без повторного вызова AI. Привязка расклада к аккаунту атомарна; повторное получение тем же аккаунтом допустимо.
- На результате показывать понятное предложение бесплатной регистрации. Существующие согласия, ограничения вопросов, приватность истории и платные расклады сохранить.
- Ограничить частоту гостевых запросов и обеспечить сохранность ключей шифрования при перезапуске Docker.

## QA / verification
- Backend: интеграционные проверки публичного превью, закрытой полной версии, ограничений расклада, повреждённого/просроченного билета, повторного открытия и привязки к аккаунту; `dotnet test backend/FutureViewer.slnx` при доступном Docker.
- Frontend: тесты гостевого старта, сохранения билета, регистрации и продолжения; `npm run type-check`, `npm test`, `npm run build`.
- Rendered browser QA через in-app browser: главная, одна карта, превью, регистрация и возврат. Playwright на desktop/mobile для точных viewport и воспроизводимой проверки с подменённым API; явно отделить эти проверки от live AI.

Публикация не запрошена; изменения и проверки выполняются локально.

## Уточнения пользователя: регистрация и удаление Telegram
- Регистрация: email, пароль и единственная изначально выключенная галочка согласия на обработку ПД. Принятие оферты, ознакомление с политикой и подтверждение 18+ явно связать с нажатием кнопки создания аккаунта. Необязательные согласия не запрашивать и не включать.
- Полностью удалить работающую интеграцию Telegram: профиль, настройки, админку, API, бот, SDK, уведомления, конфигурацию и достижения за привязку. Сохранить возможность читать старые миграции и юридические записи; не менять номера исторических enum.
- Миграцией удалить больше не используемые поля привязки и отозвать старое согласие Telegram. Применение к production не запрошено.
- Обновить проверки и документацию. QA: type-check, frontend unit tests/build, backend tests с Docker, browser QA компактной регистрации на desktop/mobile, проверки отсутствия старых API и автоматических Telegram-отправок.
