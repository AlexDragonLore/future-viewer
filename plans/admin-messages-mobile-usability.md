# Сообщения и удобство админки

## Изменения

- Добавить стартовый раздел «Сообщения»: последние сохранённые вопросы и ответы ИИ, поиск по вопросу/email, пагинация, переход к пользователю.
- В административном API показывать сохранённые расклады, включая скрытые из пользовательской истории, с явной отметкой скрытия. Не восстанавливать отсутствующий старый текст.
- В карточке пользователя раскрывать полный вопрос и ответ ИИ, показывать тексты отзывов; улучшить закрытие, фокус и работу на телефоне.
- Упростить существующие списки: понятные русские названия, удобные поиск/фильтры, обновление, мобильные карточки, второстепенные действия отдельно от чтения сообщений.
- Сохранить ограничение Admin на сервере и маршрутах, не записывать содержимое сообщений в логи.

## QA / verification

- Backend: проверки авторизации, содержимого, поиска, пагинации и видимости мягко удалённых записей; `dotnet test backend/FutureViewer.slnx`.
- Frontend: тесты загрузки/ошибок и переключения выбранного пользователя, `npm test`, `npm run type-check`, `npm run build`.
- Playwright: админские фикстуры, чтение полного текста, поиск, переход в карточку пользователя и возврат, отзывы, отсутствие обрезания на 393px и desktop.
- Rendered QA через in-app browser: локальная тестовая админская сессия, проверка сообщений/карточки пользователя на мобильной и настольной ширине. Не изменять реальные аккаунты и сообщения.

Публикация в этой задаче не запрошена; изменения готовятся и проверяются локально.

## Результат проверки

- `dotnet test backend/FutureViewer.slnx --nologo`: 375 тестов прошли.
- `npm test`: 278 тестов прошли; `npm run type-check` и `npm run build` прошли.
- Admin Playwright: 4 сценария прошли в desktop и mobile Chromium; SEO-проверки после добавления названия вкладки: 17 тестов прошли.
- In-app browser: проверены сообщения, полный ответ, карточка пользователя, список пользователей, отзывы и статистика на 393px; сообщения и пользователи также проверены на 1280px. Использованы локальные фикстуры.
