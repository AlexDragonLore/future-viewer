# Тест рекламы с общим пределом 5 000 ₽

## Задача и ограничения

Настроить измеримый тест Яндекс Директа для alex-taro.ru. Последнее указание пользователя: 5 000 ₽ на весь тест, включая НДС, вместо 5 475 ₽ каждую неделю. Не пополнять счёт и не включать автоматическое продление. Окупаемость оценивается по фактическим оплатам и расходам; результат рекламы не гарантируется.

## Реализация

1. Остановить прежний «Простой старт» № 1923114994547047225, проверить статус.
2. В счётчике 113366341 отключить автоматические цели, Вебвизор, электронную коммерцию, Тег Менеджер и Advanced Matching. Создать восемь точных событий существующей воронки; основной лид — email_verified, оплата — payment_completed с текущим доходом 300 ₽. Доход остальных целей оставить пустым.
3. Сделать платное предложение видимым после бесплатного результата и компактно на главной, не затрудняя бесплатный первый шаг. Использовать фактическую цену и период из публичной конфигурации; скрывать предложение при отключённой оплате или активном доступе. Продолжение гостевой карты остаётся бесплатным после регистрации и подтверждения почты.
4. Подготовить ЕПК с ручным подключением счётчика, показами в поиске, узкими запросами и минус-фразами, честным описанием бесплатного начала и платного доступа, техническими UTM-метками. Ограничить суммарный бюджет на период до 5 000 ₽ с налогом. При ставке НДС 22% поле без НДС — не более 4 098 ₽. Отключить продолжение показов после периода и автоматическое изменение бюджета. Проверить реальные поля интерфейса перед сохранением и запуском.
5. Обновить инструкцию в docs/yandex-direct-setup.md: настройки, цели, фактический бюджет и период, оценка регистраций, покупок и окупаемости. При цене 300 ₽ 17 покупок дают 5 100 ₽ выручки; прибыль дополнительно учитывает комиссии, налоги и стоимость ИИ.

## QA / verification

- Проверить сохранённый статус старой кампании, восемь идентификаторов целей, отключённые функции счётчика, бюджет и срок новой кампании в браузере. Сохранить скриншоты результата. Не отправлять искусственные конверсии и не проводить реальные тестовые платежи.
- Для изменений сайта выполнить npm run type-check, связанные компонентные тесты и npm run build. Проверить главную и завершённый результат в отрендеренном браузере на desktop и 390×844; проверить отсутствие горизонтального переполнения, условия видимости цены, работающий бесплатный CTA и корректный переход к оплате. Авторизованный результат можно проверить с безопасным локальным mock API; реальные регистрация/платёж для QA не требуются.
- На production проверить cookie opt-in и загрузку реального счётчика, отсутствие tag_phono.js после отключения Advanced Matching и отсутствие ошибок консоли. Браузерные события не заменяют сверку платежей с провайдером.

## Deploy

- Работать в чистом managed worktree production-guest-seo, ветка codex/production-guest-seo. Сохранить все посторонние изменения исходного checkout.
- После QA commit и push ветки; обычным fast-forward обновить origin/main без force push.
- Собрать frontend linux/amd64 с VITE_SITE_URL=https://alex-taro.ru и VITE_YANDEX_METRICA_ID=113366341, доставить образ на deploy@80.87.104.245. Обновить checkout /opt/future-viewer и только FV_IMAGE_TAG в защищённом /opt/fv-app/.env.production. Сохранить текущий backend образ и legacy edge / Janetka.
- Обновить только frontend: sudo -n docker compose --env-file /opt/fv-app/.env.production -f docker-compose.prod.yml -f docker-compose.prod.prebuilt.yml -f docker-compose.prod.legacy-edge.yml -p future-viewer up -d --no-build --pull never --no-deps frontend.
- Проверить sudo -n docker compose --env-file /opt/fv-app/.env.production -f docker-compose.prod.yml -p future-viewer ps, GET https://alex-taro.ru/health, production browser smoke главной/цены/мобильного футера и HTTP https://janetka.ru. Завершать задачу после deploy и этой проверки.
