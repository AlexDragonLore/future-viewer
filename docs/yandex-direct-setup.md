# Яндекс Директ: запуск и подсчёт лидов

Инструкция для `https://alex-taro.ru`, счётчик Метрики **113366341**. Названия пунктов сверены с официальной документацией Яндекса 3 октября 2026 года; интерфейс кабинета может немного отличаться.

SEO помогает получать переходы из обычной поисковой выдачи. Директ приводит платные переходы. Метрика связывает переходы с полезными действиями на сайте. Для оценки рекламы главным лидом здесь считаем **новую регистрацию с подтверждённой почтой** — цель `email_verified`. Отправленная форма регистрации без подтверждения — отдельный промежуточный результат `registration_submitted`.

## 1. Подготовить сайт

Отправка писем уже настроена: production использует существующий ящик `no-reply@alex-taro.ru` через HTTPS REG.RU, поскольку исходящий SMTP на сервере заблокирован. Создавать почту заново не требуется. После обновления сайта проверьте весь путь: бесплатная карта → часть толкования → регистрация → настоящее письмо → подтверждение → полное толкование той же карты. Для анализа продаж дополнительно проверьте успешную оплату через существующий платёжный провайдер. Событие покупки должно появляться только после подтверждения платежа сервером.

Сайт запускает Метрику после выбора категории «Аналитика» в настройках cookies. Вебвизор выключен. Посетители, отказавшиеся от аналитики, в этот счётчик не попадут: отчёты показывают измеренную часть аудитории, а не все регистрации в базе.

## 2. Открыть счётчик 113366341 и проверить настройки

Для этого сайта владелец предоставил номер **113366341**. Используйте этот счётчик; создавать второй не требуется. Его настройки и наличие целей нужно проверить в вашем кабинете: изменения кода сайта сами по себе не создают цели в аккаунте Яндекса.

1. Откройте [Яндекс Метрику](https://metrika.yandex.ru/) под аккаунтом владельца и найдите счётчик **113366341**. Если его нет в списке, проверьте логин или запросите доступ у владельца; не создавайте другой счётчик вместо него.
2. В настройках проверьте адрес сайта `alex-taro.ru`. Название для удобства можно указать `Алекс Таро — сайт`.
3. Проверьте московский часовой пояс и рубли. Опцию **Вебвизор, карта скроллинга, аналитика форм** оставьте выключенной.
4. Сверьте номер **113366341**. Это номер всего счётчика, а не идентификатор отдельной цели.

Откройте **Настройки → Счётчик** и выключите **Автоматические цели**. В блоке безопасности и использования данных также выключите **Использовать дополнительные настройки отслеживания** — функцию Advanced Matching. Для этой воронки достаточно восьми явных событий ниже; автоматический сбор форм и контактных данных не нужен. [Настройки счётчика](https://yandex.ru/support/metrica/ru/general/counter-general), [автоматические цели](https://yandex.ru/support/metrica/ru/general/auto-goals).

Поля счётчика описаны в [инструкции Яндекса](https://yandex.ru/support/metrica/ru/general/creating-counter); доступ — в [настройках прав](https://yandex.ru/support/metrica/ru/general/access).

## 3. Подключение номера к сайту

Настройка со стороны разработчика подготовлена: номер **113366341** указан в production env и переменной репозитория GitHub Actions, фронтенд-образ собран с этим номером. Повторять техническую настройку не нужно. После публикации проверить фактическую отправку событий по шагу 5; цели в кабинете Яндекса проверяются отдельно по шагу 4.

Для последующих сборок сохраняется это значение:

```dotenv
VITE_YANDEX_METRICA_ID=113366341
```

В production значение хранится в `/opt/fv-app/.env.production`. Значения `VITE_*` встраиваются при сборке: простого перезапуска уже собранного контейнера недостаточно. Для локальной проверки используется `frontend/.env.local`.

В **Settings → Secrets and variables → Actions → Variables** репозитория уже задана переменная `VITE_YANDEX_METRICA_ID` со значением **113366341**: production workflow передаёт её как build arg с тем же именем. Сохраните это значение при следующих обновлениях. Пустая Actions variable собирает фронтенд без счётчика, даже если номер есть в серверном runtime env. При ручной пересборке используется `--build-arg VITE_YANDEX_METRICA_ID=113366341`; prebuilt image должен содержать нужное значение.

Для запуска достаточно этого номера счётчика и согласия посетителя на категорию «Аналитика». Отдельный флаг документарного утверждения для включения Метрики не требуется. Если номер не попал в сборку, цели в Метрику не отправляются. Фактическое подключение подтвердите проверкой из шага 5.

На сайте выбор находится в **Настройки cookies → Детальная настройка → Аналитические → Сохранить настройки**. Галочка согласия на обработку персональных данных при регистрации сама по себе Метрику не включает. Кнопка **Принять необходимые** оставляет её выключенной; изменить решение можно через **Настройки cookies** внизу страницы.

Дополнительный стандартный скрипт счётчика в HTML, Tag Manager или CMS вставлять не нужно: сайт уже содержит загрузчик и отправку событий. Повторная установка создаст дублирующие просмотры.

## 4. Создать цели

В счётчике **113366341** откройте **Цели** и проверьте восемь идентификаторов ниже. Для отсутствующих нажмите **Добавить цель**, выберите тип **Целевое событие** — раньше он назывался «JavaScript-событие». Условие — **совпадает**, идентификатор — точное значение из таблицы. Название для человека можно написать по-русски. Существующие цели с этими идентификаторами повторно создавать не нужно. Сайт уже вызывает `reachGoal`; самостоятельно добавлять код на кнопки не требуется. [Создание целевого события](https://yandex.ru/support/metrica/ru/general/goal-js-event).

| Название | Точный идентификатор | Что измеряет |
| --- | --- | --- |
| Начал бесплатный расклад | `guest_reading_started` | Начало запроса гостевой карты; не означает, что результат успешно получен |
| Увидел часть толкования | `guest_preview_viewed` | Показ гостевого результата |
| Открыл регистрацию | `registration_started` | Начало пути регистрации |
| Отправил регистрацию | `registration_submitted` | Сервер принял форму; почта ещё не подтверждена. Ответ может быть таким же для уже существующего адреса, поэтому это не число новых аккаунтов |
| **Подтвердил почту — лид** | **`email_verified`** | Успешное подтверждение почты новой регистрации |
| Открыл полное толкование | `guest_reading_unlocked` | Полный результат гостевой карты после входа |
| Начал оплату | `payment_started` | Сервер создал платёж, сайт получил проверенный адрес перехода к провайдеру |
| Оплатил | `payment_completed` | Сервер подтвердил оплату конкретного заказа; действующая подписка сама по себе не считается новой оплатой |

Добавьте `email_verified` в избранные цели. Первую кампанию оценивайте по ней. Не складывайте цели между собой: один человек может пройти всю воронку и выполнить несколько действий. `guest_reading_started` и `registration_started` полезны для поиска потерь в воронке, но сами по себе ещё не лиды.

## 5. Проверить цели до запуска рекламы

1. Откройте сайт в отдельном тестовом профиле браузера по адресу:

   ```text
   https://alex-taro.ru/?utm_source=qa&utm_medium=test&utm_campaign=prelaunch&utm_content=manual&_ym_debug=2
   ```

2. Разрешите категорию **Аналитика** в настройках cookies. Откройте панель отладки Метрики и проверьте номер счётчика **113366341**.
3. Пройдите гостевой расклад и регистрацию новым тестовым email. В панели **Events / Console** должны последовательно появляться нужные события из таблицы.
4. Подтвердите почту в том же профиле браузера. Проверьте `email_verified` и после открытия продолжения — `guest_reading_unlocked`. Повторите путь с письмом, открытым в новой вкладке того же браузера.
5. Если панель не появилась, используйте `?_ym_debug=1` и консоль браузера. Этот способ поддерживается для предыдущего кода счётчика. [Проверка целей и отладчик](https://yandex.ru/support/metrica/ru/general/check-goal).
6. Проверьте противоположный случай: после отказа от аналитики обращения к счётчику и события отсутствуют. Для теста оплаты `payment_started` не должен превращаться в `payment_completed` при отмене либо ошибке платежа.

Тестовый сегмент `utm_source=qa` исключайте из рекламных отчётов. Для обычных собственных посещений включите **Настройка → Фильтры → Не учитывать мои визиты**. Фильтр привязан к браузеру с авторизацией владельца Метрики, поэтому проверять отправку целей нужно в отдельном профиле или инкогнито. [Фильтры Метрики](https://yandex.ru/support/metrica/ru/general/filters).

## 6. Создать кампанию в Директе

1. Откройте [Яндекс Директ](https://direct.yandex.ru/) под тем же аккаунтом. Нажмите **Добавить → Кампанию → Режим эксперта → Единая перфоманс-кампания**.
2. Укажите `https://alex-taro.ru/`. Для первого понятного теста выберите показы **на Поиске**; отдельную кампанию в РСЯ можно проверить позднее. Это рекомендация для раздельной оценки источников, а не гарантия более дешёвых лидов. [Настройка ЕПК и мест показа](https://yandex.ru/support/direct/ru/unified-performance-campaign/create-campaign).
3. В блоке **Счётчики Метрики** выберите **113366341**. Если он принадлежит другому логину, владелец добавляет логин рекламного кабинета через **Настройки → Доступ → Индивидуальный доступ**. Для просмотра отчётов достаточно доступа на просмотр; создавать или менять цели может пользователь с соответствующими правами. [Права на счётчик](https://yandex.ru/support/metrica/ru/general/access).
4. В стратегии выберите основное целевое действие **Подтвердил почту** (`email_verified`). Если используете стратегию «Максимум конверсий», учитывайте, что новому счётчику ещё предстоит накопить данные. Для первоначального ограниченного теста допустима стратегия «Максимум кликов» с заданным бюджетом; лиды при этом всё равно отслеживаются. [Использование целей Метрики в Директе](https://yandex.ru/support/direct/ru/technologies-and-services/metrika-in-direct).
5. Задайте регионы, где хотите привлекать пользователей, расписание и бюджет, который готовы потратить на тест. Сразу определите предельную приемлемую стоимость подтверждённой регистрации. Универсального бюджета или гарантированного числа лидов нет.
6. Создайте небольшую группу релевантных фраз: например, `карта таро онлайн`, `таро одна карта`, `карта дня онлайн`. Это стартовые гипотезы, их нужно уточнять по фактическим поисковым запросам. Исключайте запросы о работе, обучении и покупке физических колод, если они не соответствуют вашему предложению.
7. Используйте честное объявление. Пример заголовка: **«Открой карту Таро бесплатно»**. Пример текста: **«Одна карта и часть толкования сразу. Продолжение — после регистрации. Интерпретация с ИИ.»** Не обещайте весь расклад без регистрации или гарантированный результат.
8. Проверьте объявления, пройдите модерацию и запускайте показы после проверки целей.

## 7. Добавить рекламные метки

В блок **Параметры URL** на уровне кампании вставьте строку **без начального `?`**:

```text
utm_source=yandex&utm_medium=cpc&utm_campaign={campaign_id}&utm_content={ad_id}
```

Директ подставит номер кампании и объявления. Параметры на уровне кампании добавляются к ссылкам объявлений; проверьте, что настройки групп и объявлений их не переопределяют. [Единые параметры URL](https://yandex.ru/support/direct/ru/statistics/url-tags-for-camping), [поддерживаемые динамические параметры](https://yandex.ru/support/direct/ru/statistics/url-tags).

Ключевые фразы и поисковые запросы смотрите в отчётах самого Директа. Сайт не передаёт `utm_term` в счётчик: это свободный текст, который может содержать личные сведения. Для связи рекламы с лидами используются источник, канал, номер кампании и объявления.

Директ добавляет `yclid` автоматически, он помогает связать визит с рекламным кликом. Не подставляйте выдуманный `yclid`: такая ссылка не проверяет настоящую рекламную атрибуцию. После старта проверьте один реальный рекламный переход: конечная страница открылась, `yclid` и UTM пережили редиректы, а счётчик связался с нужной кампанией. [Связь Директа с Метрикой](https://yandex.ru/support/metrica/ru/general/direct).

## 8. Узнать число лидов и стоимость

В Метрике откройте **Конверсии**, выберите `email_verified`, одинаковый период и сегмент рекламного трафика нужной кампании. Включите показатели **Целевые посетители** и **Конверсия на посетителя**. Для числа людей используйте целевых посетителей, а не сумму достижений: один посетитель может выполнить цель несколько раз. Посетитель Метрики также не всегда равен одному аккаунту в базе. [Показатели отчёта «Конверсии»](https://yandex.ru/support/metrica/ru/reports/conversion).

Для расходов откройте в Метрике **Отчёты → Источники → Директ, расходы** и выберите эту же цель. Для доступа к расходам у логина должен быть доступ и к счётчику, и к рекламному аккаунту. [Отчёт «Директ, расходы»](https://yandex.ru/support/metrica/ru/sources/direct-clicks).

В Директе откройте **Мастер отчётов**, задайте период, кампанию, цель `email_verified` и добавьте расход, клики, конверсии, CR, CPA. Группируйте по кампаниям и объявлениям, затем по поисковым запросам. [Оценка performance-кампании](https://yandex.ru/support/direct/ru/statistics/performance-stat-guide).

Сохраняйте ежедневную или недельную таблицу:

| Показатель | Как считать |
| --- | --- |
| Расход | Расход выбранной кампании за период |
| Измеренные подтверждённые лиды | Целевые посетители по `email_verified` из рекламного сегмента |
| CPL — стоимость подтверждённого лида | Расход / измеренные подтверждённые лиды |
| Конверсия посетителей в лид | Целевые посетители / посетители рекламного сегмента × 100% |
| Отправленные регистрации | Отдельно `registration_submitted`; сравнение с подтверждениями показывает потери на письме |
| Подтверждённые покупки | Отдельно `payment_completed`; сопоставляйте с успешными платежами в сервисе |

Пример расчёта, а не прогноз: при расходе 3 000 ₽ и 15 измеренных подтверждённых лидах CPL = 200 ₽. Если лидов нет, CPL не определён; проверьте работоспособность пути, доставку писем, цели и соответствие рекламы прежде, чем увеличивать бюджет.

Установите одну модель атрибуции для сравнения отчётов — например, **Последний значимый переход кросс-девайс** — и записывайте её рядом с результатами. Старые варианты «Последний значимый переход» и «Последний переход из Директа» отключены с 20 мая 2026 года. [Актуальные модели атрибуции](https://yandex.ru/support/metrica/ru/reports/attribution-model).

Смотрите период с запасом для отложенных подтверждений. Клики, визиты, люди и конверсии — разные величины; они не обязаны совпадать. Блокировщики, отсутствие согласия, другой браузер при открытии письма и отложенный платёж могут скрыть часть событий или изменить источник. Текущие браузерные цели не заменяют полный подсчёт регистраций и платежей на сервере; автоматический импорт офлайн-конверсий — отдельная интеграция. [Передача конверсий с привязкой к `yclid`](https://yandex.ru/support/metrica/ru/data/yclid).

## 9. Подключить Вебмастер для SEO

1. Откройте [Яндекс Вебмастер](https://webmaster.yandex.ru/) и найдите существующий сайт `https://alex-taro.ru/`. В проект уже добавлен метатег подтверждения `3e5ca7086b4b140e`; создавать подтверждение заново не требуется, если сайт есть в вашем аккаунте и права подтверждены.
2. Если сайт ещё не отображается, добавьте точный адрес `https://alex-taro.ru/` и проверьте существующий метатег. Если ваш аккаунт выдаёт другой код, задайте его в `VITE_YANDEX_VERIFICATION` при сборке, проверьте исходный HTML после публикации и нажмите **Подтвердить**. Альтернатива — TXT-запись в DNS. [Подтверждение прав](https://yandex.ru/support/webmaster/ru/service/rights).
3. В разделе **Индексирование → Файлы Sitemap** отправьте `https://alex-taro.ru/sitemap.xml`. Проверьте доступность sitemap и `robots.txt`, затем следите за статусом обработки. [Файлы Sitemap](https://yandex.ru/support/webmaster/ru/indexing-options/sitemap).
4. Следите за диагностикой и страницами в поиске. Для SEO оценивайте поисковые переходы отдельно от `utm_medium=cpc`; рост видимости в поиске и результат рекламной кампании — разные отчёты.

Номер Метрики для этого проекта — **113366341**. После подключения проверьте восемь целей в кабинете и пройдите тестовый путь из шага 5, затем связывайте счётчик с кампанией Директа. Подтверждение Вебмастера уже предусмотрено в проекте; новый код требуется только при смене аккаунта или способа подтверждения. Пароли от Яндекса передавать разработчику не нужно.
