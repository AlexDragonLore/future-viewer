## 3. Подключение номера к сайту

Номер **113366341** подключён к сайту, указан в production env и переменной репозитория GitHub Actions; фронтенд-образ собран с этим номером. Повторять техническую настройку не нужно. Для последующих сборок сохраняется это значение:

```dotenv
VITE_YANDEX_METRICA_ID=113366341
```

В production значение хранится в `/opt/fv-app/.env.production`. Значения `VITE_*` встраиваются при сборке: простого перезапуска уже собранного контейнера недостаточно. Для локальной проверки используется `frontend/.env.local`.

В **Settings → Secrets and variables → Actions → Variables** репозитория уже задана переменная `VITE_YANDEX_METRICA_ID` со значением **113366341**: production workflow передаёт её как build arg с тем же именем. Сохраните это значение при следующих обновлениях. Пустая Actions variable собирает фронтенд без счётчика, даже если номер есть в серверном runtime env. При ручной пересборке используется `--build-arg VITE_YANDEX_METRICA_ID=113366341`; prebuilt image должен содержать нужное значение.

Для запуска достаточно этого номера счётчика и согласия посетителя на категорию «Аналитика». Отдельный флаг документарного утверждения для включения Метрики не требуется. Если номер не попал в сборку, цели в Метрику не отправляются. Фактическое подключение подтвердите проверкой из шага 5.

На сайте выбор находится в **Настройки cookies → Детальная настройка → Аналитические → Сохранить настройки**. Галочка согласия на обработку персональных данных при регистрации сама по себе Метрику не включает. Кнопка **Принять необходимые** оставляет её выключенной; изменить решение можно через **Настройки cookies** внизу страницы.

Дополнительный стандартный скрипт счётчика в HTML, Tag Manager или CMS вставлять не нужно: сайт уже содержит загрузчик и отправку событий. Повторная установка создаст дублирующие просмотры.

## 7. Проверить рекламные метки

В блоке **Параметры URL** на уровне подготовленной кампании используется строка **без начального `?`**:

```text
utm_source=yandex&utm_medium=cpc&utm_campaign={campaign_id}&utm_content={ad_id}
```

Директ подставит номер кампании и объявления. Параметры на уровне кампании добавляются к ссылкам объявлений; проверьте, что настройки групп и объявлений их не переопределяют. [Единые параметры URL](https://yandex.ru/support/direct/ru/statistics/url-tags-for-camping), [поддерживаемые динамические параметры](https://yandex.ru/support/direct/ru/statistics/url-tags).

В подготовленной ЕПК уже используется этот набор из четырёх полей. `utm_term` не добавляется.

Ключевые фразы и поисковые запросы смотрите в отчётах самого Директа. Сайт не передаёт `utm_term` в счётчик: это свободный текст, который может содержать личные сведения. Для связи рекламы с лидами используются источник, канал, номер кампании и объявления.

Директ добавляет `yclid` автоматически, он помогает связать визит с рекламным кликом. Не подставляйте выдуманный `yclid`: такая ссылка не проверяет настоящую рекламную атрибуцию. После старта проверьте один реальный рекламный переход: конечная страница открылась, `yclid` и UTM пережили редиректы, а счётчик связался с нужной кампанией. [Связь Директа с Метрикой](https://yandex.ru/support/metrica/ru/general/direct).

## 8. Узнать число лидов и стоимость

В Метрике откройте **Конверсии**, выберите `email_verified`, одинаковый период и сегмент рекламного трафика нужной кампании. Включите показатели **Целевые посетители** и **Конверсия на посетителя**. Для числа людей используйте целевых посетителей, а не сумму достижений: один посетитель может выполнить цель несколько раз. Посетитель Метрики также не всегда равен одному аккаунту в базе. [Показатели отчёта «Конверсии»](https://yandex.ru/support/metrica/ru/reports/conversion).

Для расходов откройте в Метрике **Отчёты → Источники → Директ, расходы** и выберите эту же цель. Для доступа к расходам у логина должен быть доступ и к счётчику, и к рекламному аккаунту. [Отчёт «Директ, расходы»](https://yandex.ru/support/metrica/ru/sources/direct-clicks).

В Директе откройте **Мастер отчётов**, задайте период, кампанию, цель `email_verified` и добавьте расход, клики, конверсии, CR, CPA. Группируйте по кампаниям и объявлениям, затем по поисковым запросам. [Оценка performance-кампании](https://yandex.ru/support/direct/ru/statistics/performance-stat-guide).

Для этого теста выбирайте кампанию **715035567**, а не все кампании аккаунта. В расходах включите **НДС**: в отчётах за 2026 год применяется 22%. Если сопоставлять продажи с расходом без налога, результат окажется завышен. [НДС в отчётах](https://yandex.ru/support/direct/ru/statistics/new-reports-wizard/settings/tax).

Сохраняйте ежедневную или недельную таблицу:

| Показатель | Как считать |
| --- | --- |
| Расход | Расход выбранной кампании за период **с НДС** |
| Измеренные подтверждённые лиды | Целевые посетители по `email_verified` из рекламного сегмента |
| CPL — стоимость подтверждённого лида | Расход / измеренные подтверждённые лиды |
| Конверсия посетителей в лид | Целевые посетители / посетители рекламного сегмента × 100% |
| Отправленные регистрации | Отдельно `registration_submitted`; сравнение с подтверждениями показывает потери на письме |
| Подтверждённые покупки | Отдельно `payment_completed`; сопоставляйте с фактически успешными платежами YooKassa, исключая отменённые и возвращённые |
| Стоимость оплаченного заказа | Расход с НДС / подтверждённые оплаченные заказы из рекламного трафика |
| Результат после расходов | Поступления по подтверждённым заказам − возвраты − комиссии − налоги − переменные расходы сервиса − расход рекламы с НДС |

Пример расчёта, а не прогноз: при расходе 3 000 ₽ и 15 измеренных подтверждённых лидах CPL = 200 ₽. Если лидов нет, CPL не определён; проверьте работоспособность пути, доставку писем, цели и соответствие рекламы прежде, чем увеличивать бюджет.

При сравнении отчётов выбирайте одинаковую модель атрибуции, согласованную с моделью стратегии кампании, и записывайте её рядом с результатами. Не меняйте модель только ради более красивой цифры. Старые варианты «Последний значимый переход» и «Последний переход из Директа» отключены с 20 мая 2026 года. [Атрибуция Директа](https://yandex.ru/support/direct/ru/statistics/attribution-model), [актуальные модели Метрики](https://yandex.ru/support/metrica/ru/reports/attribution-model).

Смотрите период с запасом для отложенных подтверждений. Клики, визиты, люди и конверсии — разные величины; они не обязаны совпадать. Блокировщики, отсутствие согласия, другой браузер при открытии письма и отложенный платёж могут скрыть часть событий или изменить источник. Текущие браузерные цели не заменяют полный подсчёт регистраций и платежей на сервере; автоматический импорт офлайн-конверсий — отдельная интеграция. [Передача конверсий с привязкой к `yclid`](https://yandex.ru/support/metrica/ru/data/yclid).

### Короткая проверка оператора

1. **Статус и лимит:** запуск ЕПК 715035567 принят, оба объявления сейчас на модерации / обрабатываются. Проверьте одобрение и фактические показы после **4 октября**; начало не гарантировано до завершения модерации. Старая SMB остаётся остановленной. Лимит теста — 5000 ₽ с НДС на период **04–17 октября** с остановкой в конце; новые даты, бюджет или автоплатёж сами не включайте.
2. **Лиды:** Метрика → Конверсии → `email_verified` (668270829), рекламный сегмент этой ЕПК, целевые посетители. Отправленные регистрации и старт расклада не прибавляйте к лидам; собственные тесты исключайте.
3. **Продажи:** отдельно `payment_completed` (668281352). Сверьте с успешными заказами сервиса и реальными платежами YooKassa; переход на страницу успеха, начало оплаты или действующая подписка сами по себе ещё не новая продажа. Не считайте каждое достижение цели отдельным заказом.
4. **Расход и качество:** Мастер отчётов → эта кампания → тот же период и атрибуция → расход **с НДС**, клики, лиды, покупки. По отчёту «Поисковые запросы» исключайте нерелевантные запросы; не повышайте бюджет из-за кликов или высокого CTR без оплаченных результатов.
5. **Окупаемость:** при полном расходе лимита и покупке за 300 ₽ **17 заказов = 5100 ₽ валовых поступлений** — это только покрытие рекламы 4999,56 ₽ до комиссий, налогов, возвратов и расходов сервиса. После этих вычетов 17 заказов может не хватить. Для одинаковых заказов считайте `округлить вверх(расход рекламы с НДС / чистый вклад одного заказа)`, где чистый вклад = 300 ₽ минус фактические комиссии, налоги и переменные расходы. Если чистый вклад не положительный, число заказов не решает проблему. Не используйте статический доход Метрики как подтверждённую чистую прибыль.

Это измеримый ограниченный тест, без обещания окупаемости. После окончания периода сначала дождитесь отложенных оплат и сопоставьте результаты, затем принимайте отдельное решение о следующем тесте. [Оценка расходов, дохода и рентабельности](https://yandex.ru/support/direct/ru/statistics/performance-stat-guide).
